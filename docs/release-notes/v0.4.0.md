## What's new in 0.4.0

- **Git and GitHub are set up from the Control Panel, with no terminal.** The new **Accounts** page saves the name and e-mail Git signs your work with (so the first `git commit` no longer stops with "Please tell me who you are") and signs you in to GitHub: a short code, approved in your browser, nothing to copy into a terminal. It offers GitHub's private e-mail address, which works even when your e-mail is hidden on GitHub. The Welcome app has a button for it, and Overview shows when it is not done yet.
- **Your AI apps stay current, and you can see it.** The new **Apps** page shows the version of Hermes, Ollama, AppManager and each coding agent you have installed next to the newest published release, when it last changed, and an Update button. Hermes and the coding agents also update with the rest in **Updates**. A fresh Hermes install now gets the newest release, and a Hermes update sets the old copy aside and puts it back if anything goes wrong; your Hermes data is never touched.
- **NoctraOS can update itself between releases.** The updater is built in: signed, staged updates of the NoctraOS layer (theme, Start panel, Control Panel, `noc`), with a one-step way back and a "NoctraOS features" step in **Updates**. An update is applied only after its signature and SHA-256 check out, and only when this machine's turn in the staged rollout has come. If an update fails its smoke test, the machine puts the previous version back by itself. A daily timer looks for updates; the check is a plain download of two static files, and nothing is sent to us. Updates are published as they are ready; there is none yet, so the page says so.
- **Per-account migrations run at sign-in.** When an update changes something a person has already set up, a small migration brings it across at their next login. Migrations never override a choice you made yourself. `noc doctor` reports the update state, including a migration that has failed and will be retried.
- **Ollama can be updated from the Apps page.** It asks first, because it restarts the local AI service.
- **Command line:** `noc apps` and `noc accounts` do the same as the new pages.
- **Release builds are faster and safer.** The build now uses the fastest disk, builds directly on a Linux drive, and stops early when there is not enough room.
- Behind the scenes: a Control Panel keyboard shortcut now reaches every page (Ctrl+1 to Ctrl+9).

## Known issues

- **Machines installed from 0.3.2 or earlier do not have the updater yet.** Run the one-line installer once (see the README) and they get it; after that updates and the Apps page work.
- The update path is covered by unit tests with real signing. It has not yet been booted end to end (a previous release's disk, the update applied from a local mirror, then `noc doctor`).
- Updates are not yet published from the release pipeline. Pushing `v0.4.0` publishes the ISO and VM disks only; the first signed updates follow separately.
- Signing in to the coding agents (Claude Code, Codex, Gemini CLI and the others) is still done in each agent; the Control Panel does not do it yet.
- A full interactive install of the installer ISO, real hardware, and the NVIDIA and ROCm driver paths have not been tested. The ISO and the VM disks have been run in virtual machines.
- The VM disks sign in automatically as `noctraos` (password `noctraos`) with passwordless sudo. They are for trying Noctra OS, not for real work.
