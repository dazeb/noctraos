## What's new in 0.4.0

- **Installed systems can update the NoctraOS layer themselves.** The installer modules, theme, GNOME Shell extensions, search, Control Panel and `noc` now arrive as signed update bundles, without a new ISO. `noc update` has a new `noctraos` step, and the Control Panel's Updates page shows it.
- **Updates are signed and staged.** A machine applies an update only after checking the publisher's signature and the bundle's SHA-256, and only when its turn in the staged rollout has come. If an update fails its smoke test, the machine puts the previous version back by itself.
- **Updates check once a day.** A daily timer looks for a new update. Nothing is sent to us: the check is a plain download of two static files.
- **Per-account migrations run at sign-in.** When an update changes something a person has already set up, a small migration brings it across at their next login. Migrations never override a choice you made yourself.
- **`noc doctor` reports the update state**, including a migration that has failed and will be retried.

## Known issues

- A machine installed from 0.3.2 or earlier has no updater yet. Run the one-line installer from the README once; it is safe to run again. After that, `noc update` and the Control Panel handle updates.
- The update path is covered by unit tests with real signing. It has not yet been booted end to end (a previous release's disk, the update applied from a local mirror, then `noc doctor`).
- Updates are not yet published from the release pipeline. Pushing `v0.4.0` publishes the ISO and VM disks only; the first signed updates follow separately.
- Full interactive installs of the ISO, real hardware, and the NVIDIA and ROCm driver paths are still untested. The VM disks sign in automatically as `noctraos` with passwordless sudo; they are for trying Noctra OS, not for real work.
